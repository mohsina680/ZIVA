# Documentation Style Guide

Use formal, clear, university/professional-level writing. Prefer direct headings, short paragraphs, and complete explanations. Avoid unnecessary marketing language.

Required documentation qualities:
- Clear title
- Purpose and scope
- Structured headings
- Consistent terminology
- Short conclusion
- No unrelated infrastructure discussion unless explicitly requested
- Keep the Format good and total understandable
- when user tell the future process model or As-is-Processes keep the enterprise level format
